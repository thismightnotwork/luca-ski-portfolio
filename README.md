# Luca Finnis-Bernard, Alpine Skiing Portfolio

Official personal portfolio for **Luca Finnis-Bernard**: Great Britain U18 alpine ski racer,
**BASI Ski UK Level 2** instructor, Hemel Ski Race Club (HSRC) racer, instructor at The Snow
Centre Hemel and Knockhatch Adventure Park, and SnowShepherd Pro Team athlete.

Live at **https://lucafinnisbernard.co.uk**.

## Tech stack

Static HTML, CSS and vanilla JavaScript: no build step, no framework, no dependencies to
install. This keeps the site fast, easy to edit, and simple to deploy on GitHub Pages with a
custom domain.

- `index.html`: the single-page site (hero, about, skiing/performance, journey, gallery, contact)
- `about.html`: a secondary editorial about page
- `404.html`: branded not-found page, served automatically by GitHub Pages
- `styles.css`: the full design system and styles
- `data.js`: **all editable content**: race results, season stats, equipment, journey
  timeline, social links, contact form endpoint
- `app.js`: behaviour: preloader, navigation, the slalom scroll animation, reveal
  animations, the gallery/lightbox, form validation
- `course.js`: the slalom rail course model: gate layout, racing line and geometry
  validation, shared by the page and the regression test
- `scripts/`: maintenance scripts, including `check-course.mjs`, the course regression test
- `photos/`: image folder, auto-discovered by the gallery

## Editing content

Everything factual lives in **`data.js`**. To update race results, season stats, equipment,
timeline entries or social links, edit the arrays at the top of that file. No HTML or CSS
changes required.

### Adding gallery photos

1. Add an image (`.jpg`, `.jpeg`, `.png`, `.webp`, `.gif` or `.avif`) to the `photos/` folder.
2. Commit and push to `main`.
3. The gallery reads `photos/manifest.json`, generated by `scripts/build-photo-manifest.mjs`
   and regenerated automatically on every deploy by the Pages workflow, so new photos appear
   automatically. If the manifest is missing (e.g. a local edit before regenerating it), the
   gallery falls back to GitHub's public Contents API; if both sources fail it shows an error
   state with a retry button. Favicon/manifest files in `photos/` are excluded
   automatically and never shown in the gallery.

To regenerate the manifest locally (e.g. after adding photos, before committing):

```bash
node scripts/build-photo-manifest.mjs
```

Use descriptive filenames (e.g. `tignes-slalom-2026.jpg`), as filenames become part of the alt text.

### Connecting the contact form

The contact form ships in an honest, disconnected state: submitting it explains that direct
sending isn't configured yet and points visitors to social channels instead. To enable real
submissions:

1. Create a form endpoint with [Formspree](https://formspree.io), [Web3Forms](https://web3forms.com)
   or a Cloudflare Worker.
2. Set `SITE_CONFIG.formEndpoint` in `data.js` to that URL.
3. Never commit private API keys. Formspree/Web3Forms endpoint IDs are safe to expose
   client-side by design; a Worker should validate/rate-limit server-side instead.

## The slalom scroll course

A thin SVG rail runs down the left edge of the page, drawn like a course-setter's diagram: thin
red and blue **pole strokes** beside a solid racing line that finishes in an arrow. The course
is generated by **`course.js`**, which lays out each combination as one coordinated unit and
derives the racing line from the resulting gate sequence, so the line is the route through the
gates rather than a free-standing wave. The geometry follows the course-setter's diagrams: an
**open gate** is two poles across the hill with the line passing between them; a **vertical
gate** is two same-colour poles stacked down the fall line with a throat between them, which
the line passes through; a **delay** is one vertical gate, a **hairpin** two of them and a
**flush** three, each combination placed, spaced and validated as a whole (including its entry
and exit gates), with a bare **turning pole** wrapped in a pocket between them. The layout
validates spacing, overlap, throat passage, pocket wrap, clearance at both rail widths and
line smoothness, and reports problems instead of breaking the page; `index.html` keeps a static
copy of the generated path as the no-JS fallback. `node scripts/check-course.mjs` runs the
regression test, which guards the blue-red-blue flush cluster against collapsing back into
independent overlapping poles. A faint dashed fall line runs behind the
course. Red and blue poles alternate down the hill, matching the real sport, where red encodes
slalom and blue encodes giant slalom across the site. A skier-shaped marker rides the course
line, tipping into each turn along the path tangent, its shape counter-scaled so it stays crisp
at any rail width or viewport height. On mobile the rail narrows so the poles and line stay
legible; a slim progress bar at the top of the viewport mirrors scroll
progress everywhere. The moving marker is disabled under
`prefers-reduced-motion: reduce`, leaving the static course line and gates visible. The
animation never hijacks scrolling: it only reads `window.scrollY`.

## Local development

No install step is required.

```bash
# from the repository root
python3 -m http.server 8080
# then open http://localhost:8080
```

## Deployment (GitHub Pages, custom domain)

Deployment is automated by `.github/workflows/deploy.yml`:

- Runs on every push to `main`.
- Uploads the repository as a Pages artifact (no build step, since the site is already static).
- Deploys via `actions/deploy-pages`.

In **Settings → Pages**, the source should be set to **GitHub Actions**. The `CNAME` file
(containing `lucafinnisbernard.co.uk`) keeps the custom domain configured; do not remove it.

## Accessibility

Semantic HTML, visible focus states, a skip-to-content link, keyboard-operable navigation and
lightbox with focus trapping, accessible form labels/errors, and a full `prefers-reduced-motion`
mode that disables the moving marker, parallax and large entrance animations while keeping all
content immediately visible.

## Content accuracy

All race results, season statistics, qualifications and equipment listed on this site are drawn
from Luca's own published record. No results, rankings, sponsors or qualifications are invented.
Journey timeline entries without a specific confirmed date are labelled "Ongoing" or by season
rather than given an invented date.
